# دليل الأسلوب

> **دليل أسلوب Rust لشفرة المترجم.** هذا مصدره، ويعرضه الموقع في `compiler/reference/standards/style-guide/`، مولَّدًا منه بـ`tools/gen_style_guide.py`. فعدِّل هنا ثمّ شغّل المولّد، ولا تعدّل صفحة الموقع باليد.
>
> الوسمان `<قسم حالة="…">` و`</قسم>` يحيطان كلّ قسم، فيُظهر الموقع حالته شارةً (معتمد، أو مقترح، أو مؤجل، أو مفتوح، أو لم_يعالج). ويظهر الوسمان هنا على GitHub نصًّا كما هما.

**المعيارُ الحاكم لكلّ قاعدة: هل ترفض الآلةُ مخالفتَها؟** فالقاعدةُ المتروكة للمراجعة البشريّة لن تُراجَع ما دام المراجعُ واحدًا. ولذلك القواعدُ البشريّة ثلاثٌ فقط.

**أُعيدت كتابتُه لـRust (٢٠٢٦-١١-٢٠)** بعد أن صار المترجمُ بـRust (ق‑٥). **أرقامُ القواعد ثابتة:** ما لا معنى له في Rust يبقى رقمُه ويُكتب «أُسقطت» مع علّتها، ولا يُعاد رقمُه. واعتمد المالكُ الأقسامَ التي تغيّرت كلَّها (٢٠٢٦-١١-٢٠).

## الذاكرة

| # | القاعدة | الفحص |
|---|---|---|
| ٥ | **لا يدخل المخصِّصَ المجمَّع إلّا ما لا يحتاج هدمًا،** فالنصوصُ والمصفوفات خارجه | توكيدٌ ساكن (`needs_drop`) |
| ٦ | **فهارسُ بأنواعٍ مستقلّة، ومعها رقمُ جيلٍ في بناء التطوير. ويُحمل الفهرسُ لا المرجع** | المترجم · التوكيدات |
| ٧ | **لا تسريبَ ولا مؤشّراتٍ خام:** لا `Box::leak` ولا `mem::forget`، والمؤشّرُ الخامّ في صندوق الوصل `sad_llvm` وحده | clippy (`disallowed_methods`) · القاعدة ٣ |

| ٩ | **`match` على تعدادات المترجم بلا فرعٍ عامٍّ يبتلع كلَّ حالة** | clippy (`wildcard_enum_match_arm`) |
| ١٠ | **حدٌّ لعمق العوديّة،** وهدفُ تشويشٍ لفكّ UTF-8 | التشويش |

## مصدرُ الحقيقة للنصوص العربيّة

**ملفّاتُ TOML في `data/` يكتبها الإنسان، ومنها تُولَّد شفرةُ Rust للمترجم وترويساتُ C لمكتبة التشغيل.** أصلُه اقتراحُ المالك، وعُدِّل قبل اعتماده.

| # | القاعدة |
|---|---|
| ٤٢ | **ثلاثةُ أنواعٍ لا تُخلط:** بياناتُ اللغة ثوابت. ورسائلُ المستخدم دوالُّ بمعاملاتٍ مسمّاة. ومدخلاتُ الاختبار ملفّاتٌ مستقلّة |
| ٤٤ | **الشفرةُ المكتوبة يدويًّا بحروف ASCII وحدها خارج التعليقات،** ولا هروبَ إلى نطاقات العربيّة (`\u{…}`) |
| ٤٥ | **مدخلاتُ الاختبار ومخرجاتُه يكتبها إنسان،** ولا تُدمج إلّا بموافقة المالك. فالاختبارُ الذي يقرأ الثابتَ المولَّد تحصيلُ حاصل |
| ٤٦ | **القوالبُ تشير إلى الكلمات بمعرِّفها.** والمولّدُ يرفض الكلمةَ الحرفيّة، والمرادفَ المحظور، والهمزةَ المخالفة، والتكرار |
| ٤٧ | **المعرِّفُ الإنجليزيّ ثابت،** ورموزُ الأخطاء لا تُحذف ولا تُعاد |
| ٤٨ | **نظافةُ البيانات:** NFC، ولا محارفَ اتّجاهٍ ولا خفيّة، والهمزةُ بنقاط الترميز، وجداولُ Unicode المثبَّتة |
| ٤٩ | **التوليدُ أوّلُ خطوة،** وفهرسٌ مقروءٌ للوكيل |
| ٥٠ | **صيغُ الجمع، ومعاينةٌ مرسومةٌ لكلّ رسالة،** وعزلُ المعرِّف المُدرج عند الطباعة |
| ٥١ | **المولّدُ يتحقّق من كلّ مفتاحٍ ونوع** |

**ويبدأ بثلاثة ملفّات:** معجمُ المصطلحات أوّلًا (القاعدة ٢٧)، ثمّ الكلمات، وفهرسُ الأخطاء الذي تُكتب رسائلُه بمصطلحات المعجم. **وملفُّ الكلمات `data/keywords.toml`** (٢٠٢٦-١١-٢٦).

**كلماتُ اللغة والأنواع:**

| الشيء | أين يُكتب |
|---|---|
| **كلماتُ اللغة** (`إذا` و`لكل` و`طابق`…) | ملفُّ الكلمات، ومنه يولّد `build.rs` تعدادَ الكلمات وجدولَ تهجئتها للمحلِّل المعجميّ |
| **أسماءُ الأنواع الأوّليّة** (`رقمي٣٢` و`نص`…) | ملفُّ الكلمات، في قسمٍ مستقلّ |
| **معنى النوع الأوّليّ:** حجمُه وتحويلاتُه وتوليدُه | شفرةُ Rust يدويّة، تشير إليه بمعرِّفه الإنجليزيّ (`Prim::I32`) |
| **أنواعُ المكتبة** (`اختياري` و`نتيجة`…) | بص في المكتبة القياسيّة، ويعلّمها المترجمُ عناصرَ لغويّة |

ومن ملفّ الكلمات نفسِه يُولَّد تلوينُ امتداد المحرّر وصفحاتُ الموقع، فلا تختلف كلمةٌ بينها.

(تغيّر المولَّد وحده: Rust بدل ترويسات C++ · اعتُمد ٢٠٢٦-١١-٢٠)

## التزامن

**أمانُ الخيوط في الشفرة الآمنة يفرضه Rust** (`Send` و`Sync`)، فلا سباقَ بيانات خارج `unsafe`. والقواعدُ هنا للحتميّة والتنظيم.

| # | القاعدة |
|---|---|
| ٦٣ | **مجمّعُ مهامّ واحدٌ ينشئ الخيوط،** والخيطُ الرئيسيّ لا يترجم |
| ٦٤ | **سياقُ LLVM لكلّ وحدة، مفروضٌ ساكنًا:** أنواعُ طبقة الوصل ليست `Send`، فلا يعبر السياقُ خيطًا |
| ٦٥–٦٧ | **الحالةُ المشتركة ثابتةٌ أو خلف قفل،** والذرّيّاتُ في المجمّع وحده، ولا `static` بتغييرٍ داخليّ ولا `thread_local!` قابلٌ للتعديل |
| ٦٨–٧٠ | **المهامُّ بإلغاء،** والحتميّةُ باختبار خيطٍ مقابل ستّة عشر، وكاشفُ السباقات على صندوق الوصل `sad_llvm` والحشوة في مهمّةٍ مستقلّة |
| ٧١ | **لكلّ قاعدةٍ شفرةٌ مخالِفةٌ يثبت التكاملُ المستمرّ رفضَها** |

(رست، اعتُمد ٢٠٢٦-١١-٢٠)
</قسم>

## الاختبارُ والتوثيق

**المالكُ لا يراجع الشفرة، بل يراجع العرّافات:** كتلَ الموقع، والمدخلاتِ والمخرجاتِ المتوقَّعة، والاختبارَ التفاضليّ، وملفّاتِ مطابقة Unicode. فالبوّاباتُ التي تفحص الشكلَ يستوفيها الوكيلُ بلا جهد.

| # | القاعدة |
|---|---|
| ٧٢ | **طبقاتُ الاختبار:** مجموعةُ المطابقة على ملفّات ص (مواصفةٌ قابلةٌ للتنفيذ)، واختباراتُ الوحدة، والتشويش، والتفاضليّ، وكتلُ الموقع، والتكافؤ، **ومطابقةُ Unicode في كلّ طلب، والتشغيلُ على المحاكيات كلَّ ليلة** |
| ٧٣ | **اختبارُ الإصلاح يفشل على الشفرة قبله،** ويثبته التكاملُ المستمرّ |
| ٧٤ | **الاختباراتُ تُضاف ولا تُعدَّل،** وكلُّ مخرجٍ متوقَّعٍ جديدٍ «عرّافةٌ جديدة» يراجعها المالك |
| ٧٥–٧٧ | **التغطيةُ تُعرض ولا تُفرض،** والمتقلّبُ علّةٌ يُعزل آليًّا، والثقيلُ كلَّ ليلةٍ وفشلُه يفتح بلاغًا |
| ٧٨–٧٩ | **لا يُفرض وجودُ التعليق،** والثوابتُ توكيدات، وعنوانُ الطلب عربيٌّ ببادئة الوحدة |

(الجولةُ الرابعة، ٢٠٢٦-١٠-١٧)
</قسم>

## مساهمةُ الذكاء الاصطناعيّ وحمايةُ المستودع

| # | القاعدة |
|---|---|
| ٨٠ | **تعليماتُ الوكيل نواةٌ وشريحةٌ لكلّ وحدة،** ومعها دليلُ المساهم العربيّ من المصدر نفسه |
| ٨١ | **الوكيلُ بحسابٍ منفصل، وأدواتُ الفرض من الفرع الأساسيّ،** وصلاحيّاتُ التكامل المستمرّ للقراءة، وإذنٌ قبل أوّل طلبٍ لكلّ مساهم |
| ٨٢–٨٤ | **وحدةٌ لكلّ طلب، وفقرةٌ بشريّةٌ تشرح العلّة،** وأمرُ فحصٍ محلّيٍّ واحد |
| ٨٥ | **ملخّصُ المراجع يبدأ بفرق السلوك،** ويصنّف الطلبَ بالخطر |
| ٨٦–٨٩ | **سقفٌ للطلبات المنتظرة، والموافقةُ من إنسان،** والوكيلُ لا ينفّذ تعليماتٍ من نصوص الآخرين، وتدقيقٌ عشوائيٌّ أسبوعيّ |
| ٩٠ | **تفعيلٌ متدرّج:** نواةٌ في اليوم الأوّل، والباقي عند أوّل متطوّعٍ أو أوّل ألف سطر |
</قسم>
